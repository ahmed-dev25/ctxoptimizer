# SPEC.md — ctxproxy: The Agent-Run Cost Optimizer

Working name: **ctxproxy** (package `ctxproxy`, CLI `ctxproxy`).
Spec version: 2.0 (supersedes SPEC v1.0 and the "Architecture v4" docx). Language: **Python 3.11+**.

> **Positioning change (v2.0):** this is no longer a "context garbage collector." It is an
> **agent-run cost optimizer** that follows one causal chain end-to-end:
> **measure → diagnose → optimize → attribute → prevent → coach**. Context cleanup and
> cache hints are still core, but they are now *two detectors among many*: the product's
> differentiator is that every wasted token is classified, evidenced, priced, and either
> eliminated (deterministically) or explained to the user as a ranked opportunity.

This file is the single source of truth. Rules for any AI coding session working from it:

1. **Work one task at a time.** Pick one task from §22 (Roadmap). Do not implement later phases early.
2. **Tests first.** For every module, write the tests described in §20 before or alongside the code. A task is done only when `ruff check`, `mypy --strict ctxproxy`, and `pytest` all pass.
3. **Invariants (§2) are non-negotiable.** If a task seems to require violating one, stop and flag it instead of working around it.
4. **Do not invent provider API behavior.** Where this spec says *VERIFY*, check the provider's current docs or capture real traffic before coding against it. Record findings in `docs/provider-notes.md`.
5. **Never add dependencies** not listed in §6 without stating why in the PR description.
6. **Ask/flag, don't guess:** if the spec is ambiguous, list your assumption in the task summary and pick the most conservative behavior (forward the request unchanged).
7. **Keep modules small** (target < 300 lines) with typed public interfaces exactly as defined in §9–§11.
8. Do not edit this file except to append to §25 (Decision Log) or §26 (Open Questions).
9. **Waste detectors are advisory-only.** They observe, record, and rank — they never
   mutate traffic, block requests, or bill by implication (INV-16). If a detector's
   insight *can* be acted on deterministically and provably safely, it becomes a Transform
   (opt-in, guarded); otherwise it stays a Finding.

## 1. Product Summary

### 1.1 What it is
A local, transparent HTTP proxy that sits between LLM clients (Claude Code, Aider, Cline, Continue, SDK scripts, etc.) and LLM providers (Anthropic, OpenAI, Google Gemini, Ollama, OpenAI-compatible hosts). It:

1. **Measures** — records real token usage, cache hits and dollar cost for every request (ground truth from provider `usage` fields).
2. **Diagnoses** — explains *why* prompt caching missed (which block changed between consecutive requests).
3. **Optimizes** — applies deterministic, non-LLM, cache-safe payload reductions (ANSI/progress/log noise removal, error-aware truncation, duplicate tool-output back-references, byte-true cross-request substitution) and provider-specific cache hints (Anthropic `cache_control` breakpoints, OpenAI `prompt_cache_key`).
4. **Attributes** — classifies *wasted* spend into a deterministic taxonomy (redundant re-reads, unbatched fan-outs, cache-busting drift, runaway sessions, churn edits) with per-cause evidence and dollar estimates — the layer no auditor ships without an LLM, and no compressor ships at all.
5. **Prevents** — byte-true (T0) interventions only: content hash-identical to what the client already holds is substituted with *zero* semantic risk; anything lossy is opt-in, guarded, and self-quarantining.
6. **Coaches** — turns measured evidence into ranked recommendations ("your system prompt timestamp busts your cache", "3 unused MCP tool schemas bill every turn", "enable `cache_serve` — projected $X/mo"), each labeled honestly (`est.`/`sim.`).
7. **Proves savings honestly** — shows actual cost, and a clearly labeled *simulated* baseline cost of what the untouched request would likely have cost.

The v2 value chain: **fewer tokens per request** (transforms) → **higher cache hit per turn** (hints + prefix stability) → **fewer wasted calls per session** (attribution + coaching) → **fewer wasted turns** (runaway/churn detection). Layers 1–3 reduce the *bill per request*; layers 4–6 reduce the *number of dumb requests*. Both halves are the product.

### 1.2 Goals
- Zero code changes for users: set a base-URL env var.
- Never break a request that would have worked without the proxy (fail-open).
- Add negligible latency; never buffer streams.
- Local-first and private: no network calls except to the configured upstreams; no telemetry leaves the machine.
- Single install command; runs on macOS, Linux, Windows.
- Attribute spend to causes, not just contexts: for every request, "what did this buy?" and "what part of it was waste?" must be answerable from the recorded data.
- Tune itself: features that regress (fallbacks, "our-fault" drift) auto-quarantine per session instead of waiting for the user to hunt them down.

### 1.3 Non-goals (v1)
- No LLM-based summarization/compaction inside the proxy (cost, latency, nondeterminism).
- **No LLM anywhere in any intervention or verification path.** All transforms, all waste detectors, and all recommendations are deterministic. Any future "speculative" feature (model routing, fix-up interception) must cost-justify its verification LLM per Decision D15 and ships as a separate phase, never in the v1 path.
- No semantic/embedding response caching, no request rewriting between providers (no OpenAI↔Anthropic translation).
- No WebSocket/Realtime API support.
- No multi-user/team server mode, no cloud sync.
- No automatic retries of failed requests other than the single "retry-with-original" safety net (§9.7).
- No Bedrock/Vertex/Azure-specific signing support (pass-through only if headers need no re-signing — generally unsupported).
- No mutation-style behavioral interventions in v1 (vetoing tool calls, rewriting model routing): generated insights ship as **Findings** (advisory) plus **T0 byte-true transforms** only.

### 1.4 Operating modes
| Mode | Behavior | Default |
|---|---|---|
| `passthrough` | Forward unchanged; record only basic usage + latency. | no |
| `shadow` | Forward the **original** unchanged; compute what transforms *would* have done and log potential savings. | **yes (first run)** |
| `active` | Forward the transformed request; log actual + simulated baseline. | no (user opts in) |

Mode is switchable at runtime (CLI, dashboard, `x-ctxproxy-bypass` header per request).

## 2. Invariants (hard rules)

IDs are referenced in tests and code comments (`# INV-3`).

- **INV-1 Fail-open.** Any exception, timeout, or validation failure inside analysis/transform code results in forwarding the *original request bytes* untouched. Proxy bugs must never surface as client errors.
- **INV-2 Byte-exact passthrough when unchanged.** If no transform changed anything, forward the original body bytes (not a re-serialization).
- **INV-3 Never buffer streams.** Upstream response bytes are forwarded as they arrive. Usage parsing is a side-channel tee that can never raise into the forwarding path.
- **INV-4 Determinism.** `transform(x)` depends only on `x` and the config. No clocks, randomness, set/dict-ordering dependence on hash seed, or session state in content-local transforms.
- **INV-5 Idempotence.** `transform(transform(x)) == transform(x)` for every transform.
- **INV-6 Prefix stability.** For a conversation `C` and any extension `C + Δ`, the serialized transformed prefix covering `C` must be identical to `transform(C)` (for all enabled content-local transforms). Positional transforms (e.g. stale-result elision) may only change the prefix at batch boundaries (§12.8).
- **INV-7 Structure preservation.** Never reorder messages or tool definitions. Never drop, add, or rename `tool_use`/`tool_result` (or OpenAI `tool_calls`/`tool` messages) so that pairing/IDs break. Preserve all unknown fields.
- **INV-8 Don't touch reasoning.** Never modify Anthropic `thinking`/`redacted_thinking` blocks (signatures are validated), OpenAI reasoning items, or Gemini thought parts/signatures.
- **INV-9 Never touch user-authored or assistant-authored text by default.** Default transforms apply only to *tool result* content. Anything else is opt-in and documented as experimental.
- **INV-10 No-regress guard.** If a transform's output is not smaller (in estimated tokens) than its input by at least the configured minimum, discard that transform's change.
- **INV-11 Credentials stay in memory only along the forwarding path.** API keys/auth headers are forwarded, never stored or logged in plaintext (§17).
- **INV-12 Loopback only.** Bind to `127.0.0.1` / `::1` unless the user explicitly opts in with an auth token (§17).
- **INV-13 Honest numbers.** Any figure not derived from provider-reported usage is labeled *estimated* or *simulated* in the UI, API, and exports.
- **INV-14 Raw payloads are private.** Payload capture is opt-in/limited, secrets are redacted at capture time, and retention is bounded (§17).
- **INV-15 Provider errors pass through verbatim** (status, headers, body) — including 429 `retry-after`.
- **INV-16 Findings never mutate.** Waste detectors (§13.6) and recommendations (§13.7) write *only* to telemetry (SQLite, dashboard, CLI). No Finding may alter a request body, cancel/slow a forwarding path, or inject content into any payload. A Finding may *become* a feature only by graduating into a Transform that follows all transform invariants (INV-4/5/6/10) and ships opt-in.
- **INV-17 Stateful transforms are batch-boundary-anchored and self-quarantining.** Any transform using cross-request/session state (`cache_serve`, `stale_result_elision`) must (a) change the serialized prefix only at batch boundaries, exactly as §12.8 does, (b) be disabled by default, and (c) auto-quarantine per §12.14 when its guard counters trip. State must be reconstructible from the blob store (no silent loss).
- **INV-18 Honest waste.** `est_tokens_wasted`/`est_cost_usd` on every Finding is an estimate with a stated method (§13.6) — never presented as billed spend. Detector totals displayed anywhere carry the `est.` label, and a calibration error is surfaced once real usage data exists.

## 4. Architecture

### 4.1 Request lifecycle
```
Client ──HTTP──▶ [1 Ingress: route/auth/limits]
                    │
                    ▼
              [2 Classify: provider, endpoint, session, project]
                    │ (unknown endpoint → raw passthrough, skip 3-6)
                    ▼
              [3 Decode: body → dict (orjson); content-encoding check]
                    │ failure → INV-1 passthrough
                    ▼
              [4 Analyze: segments + hashes + token estimates + prefix-drift]
                    ▼
              [5 Pipeline: transforms (time-budgeted, no-regress guarded)]
                    │ mode=shadow → discard result, keep report
                    ▼
              [5b Waste: detectors over segments + session history (§13.6)
                  findings recorded ONLY; traffic path untouched (INV-16)]
                     ▼
              [6 Encode: orjson.dumps only if changed (INV-2)]
                    ▼
              [7 Forward: httpx stream to upstream]
                    │ 400/422 on mutated request → retry once with original (§9.7)
                    ▼
              [8 Tee: bytes → client (untouched) + usage parser (side-channel)]
                    ▼
              [9 Finalize: cost calc, baseline simulation, enqueue to SQLite writer]
```

### 4.2 Components
| Component | Module | Responsibility |
|---|---|---|
| Server/Ingress | `ctxproxy/server.py` | Starlette app, routes, lifespan, shared `httpx.AsyncClient`. |
| Router | `ctxproxy/routing.py` | Classify requests → `(Provider, Endpoint, upstream)` (§8). |
| Adapters | `ctxproxy/providers/*.py` | Provider-specific parsing, block iteration, usage parsing, error shaping. |
| Pipeline | `ctxproxy/pipeline.py` | Ordered transform execution, time budget, guards, reports. |
| Transforms | `ctxproxy/transforms/*.py` | Individual transforms (§12). |
| Analysis | `ctxproxy/analysis/*.py` | Segmenting, hashing, token estimation, prefix-drift, baseline simulator. |
| Waste analysis | `ctxproxy/analysis/waste.py` | Deterministic waste detectors over segments + history; findings recorded only (§13.6). |
| Recommendations | `ctxproxy/analysis/recommend.py` | Ranks config/behavior recommendations from measured evidence (§13.7). |
| Expand MCP | `ctxproxy/mcp.py` | Stdio MCP server exposing `ctxproxy_expand(ref)` for on-demand retrieval of omitted output (§12.13). |
| Pipeline guard | `ctxproxy/pipeline.py` (guard section) | Auto-quarantine rules on fallback counters / our-fault drift (§12.14). |
| Telemetry | `ctxproxy/telemetry/*.py` | Usage normalization, pricing, cost, SQLite writer, blob store. |
| Dashboard | `ctxproxy/dashboard/*` | Admin API + Jinja/HTMX UI under `/_ctxproxy/`. |
| CLI | `ctxproxy/cli.py` | Typer commands (§15). |
| Config | `ctxproxy/config.py` | TOML + env + CLI → validated `Config` (§7). |
| Licensing | `ctxproxy/licensing.py` | Offline license check, isolated for removal (§19). |

### 4.3 Concurrency model
- Single process, single asyncio event loop (`uvicorn --workers 1`; state like session caches and the SQLite writer assume one process).
- One shared `httpx.AsyncClient` (HTTP/2 enabled, connection pooling, `read=None` timeout for streams, finite connect timeout).
- CPU work (parse/transform) runs inline for payloads ≤ `offload_threshold_bytes` (default 256 KB), otherwise in `asyncio.to_thread` (§18). Transforms must be written in short, bounded steps (line-oriented) so no single call monopolizes the GIL.
- SQLite writes go through one dedicated writer thread consuming a bounded `queue.Queue`; if the queue is full, **drop telemetry, never block requests** (increment a `dropped_events` counter shown in dashboard).

## 7. Configuration

### 7.1 Sources and precedence
CLI flags > environment (`CTXPROXY_*`) > config file > defaults. Config file path: `platformdirs.user_config_dir("ctxproxy")/config.toml`. Created on first run with commented defaults. Hot-reload via `POST /_ctxproxy/api/reload`, `SIGHUP` (POSIX), or `ctxproxy reload`. Each reload computes `config_hash` (sha256 of the canonical effective transform config). `config_hash` is stored on every request, because changing transform config alters transformed bytes and causes a one-time cache miss — the dashboard must annotate that.

## 8. Routing & Provider Detection

### 8.1 Namespaces
- `/_ctxproxy/**` — dashboard, admin API, health (`/_ctxproxy/health`). Never forwarded.
- `/p/<project>/**` — optional project tag; the prefix is stripped, remainder routed normally. Lets clients without custom headers tag a project via base URL (`http://localhost:8787/p/myrepo`).
- `/u/<upstream>/**` — explicit named-upstream routing (§8.3); prefix stripped.
- Everything else — auto-detected by path.

### 8.2 Auto-detection table (first match wins)
| Method + path | Provider | Endpoint kind |
|---|---|---|
| `POST /v1/messages` | anthropic | `messages` |
| `POST /v1/messages/count_tokens` | anthropic | `passthrough` (no transforms; usage n/a) |
| `* /v1/messages/batches*`, `* /v1/files*`, `* /v1/skills*` | anthropic | `passthrough` |
| `POST /v1/chat/completions` | openai (or by header heuristic) | `chat` |
| `POST /v1/responses` | openai | `responses` |
| `POST /v1/embeddings`, `/v1/audio/*`, `/v1/images/*`, `/v1/moderations` | openai | `passthrough` |
| `POST /v1beta/models/*:generateContent`, `*:streamGenerateContent` (and `/v1/models/*:...`) | gemini | `generate` |
| `POST /api/chat`, `/api/generate` | ollama | `chat` / `generate` |
| `GET /v1/models*` (ambiguous) | Anthropic if `anthropic-version` or `x-api-key` header present; else OpenAI | `passthrough` |
| anything else | default upstream (`openai`) | `passthrough` |

Anthropic request query strings (e.g. `?beta=true`) MUST be forwarded unchanged. Gemini `key=` query params and `alt=sse` MUST be forwarded unchanged and never logged.

### 8.3 Named upstreams
`[upstreams]` defines base URLs; `kind` ∈ {`anthropic`, `openai`, `gemini`, `ollama`} selects the adapter. `/u/openrouter/v1/chat/completions` → adapter `openai`, upstream `https://openrouter.ai/api` + `/v1/chat/completions`. For non-`api.openai.com` OpenAI-kind upstreams, **never inject provider-specific fields** (INV-7 spirit): only content transforms run.

### 8.4 Upstream URL construction
`upstream_base.rstrip("/") + stripped_path + ("?" + raw_query if query)`. Preserve method. Do not follow redirects (`follow_redirects=False`) and return upstream 3xx as-is.

## 9. Proxy Core (`proxy.py`)

### 9.1 Ingress limits
- Reject nothing by default; if `Content-Length` > `max_body_bytes`, stream body upstream untransformed (passthrough) — do not buffer it.
- Support chunked request bodies: read fully only when the endpoint is a transform candidate; otherwise stream through.
- `Expect: 100-continue` — let uvicorn/httpx handle; do not special-case.

### 9.2 Header handling
- Strip hop-by-hop headers in both directions: `connection, keep-alive, proxy-authenticate, proxy-authorization, te, trailers, transfer-encoding, upgrade` (plus any listed in `Connection`).
- Strip `host` (httpx sets it), `content-length` (recomputed), `accept-encoding` (replaced when `force_identity_encoding`), and all `x-ctxproxy-*`.
- Forward everything else verbatim, including `authorization`, `x-api-key`, `anthropic-version`, `anthropic-beta`, `openai-*`, `user-agent`, `x-stainless-*`.
- Response: forward status and headers except hop-by-hop and `content-length`/`content-encoding` handling per §9.4. Add `x-ctxproxy-request-id` (response only; harmless).

### 9.3 Streaming
```python
async def forward(request_ctx, upstream_request) -> StreamingResponse:
    upstream = await client.send(upstream_request, stream=True)
    parser = adapter.new_usage_parser(request_ctx)      # never raises outward

    async def body():
        try:
            async for chunk in upstream.aiter_raw():
                try: parser.feed(chunk)                 # INV-3: isolated
                except Exception: parser.disable()
                yield chunk
        finally:
            await upstream.aclose()
            finalize(request_ctx, parser.result(), outcome=...)  # completed | client_disconnect | upstream_error
    return StreamingResponse(body(), status_code=upstream.status_code, headers=clean(upstream.headers))
```
- Client disconnect → generator closed → `finally` closes upstream (stops provider billing for abandoned streams where possible) and records `outcome="client_disconnect"` with partial usage.
- Non-streaming JSON responses: read once, parse usage, return unchanged bytes.
- Time-to-first-byte (`ttfb_ms`) = upstream headers received; `proxy_overhead_ms` = time from ingress to upstream request send (decode+analyze+transform+encode).

### 9.4 Compression
v1 default: send `Accept-Encoding: identity` upstream (`force_identity_encoding=true`) so SSE/JSON is plaintext for the usage tee. If disabled, the parser must decompress gzip/deflate (`zlib.decompressobj`) incrementally while still forwarding raw bytes and the `content-encoding` header untouched. Brotli/zstd responses → disable parsing for that request (telemetry marked `usage_source="none"`).

### 9.5 Request body encoding
If the request has `content-encoding` (gzip/deflate/zstd/br): decode only if the codec is available and the decoded size is within limits; if transformed, send **uncompressed** and drop the header; if unsupported → INV-1 passthrough untouched. Non-JSON or multipart bodies → passthrough.

### 9.6 Error shaping (proxy-originated failures only)
- Upstream connect/TLS/DNS failure → HTTP 502 with a provider-shaped body:
  - Anthropic: `{"type":"error","error":{"type":"api_error","message":"ctxproxy: upstream unreachable: <reason>"}}`
  - OpenAI-kind: `{"error":{"message":"ctxproxy: upstream unreachable: <reason>","type":"server_error","code":"upstream_unreachable"}}`
  - Gemini: `{"error":{"code":502,"message":"...","status":"UNAVAILABLE"}}`
  - Ollama: `{"error":"ctxproxy: upstream unreachable: <reason>"}`
- Upstream timeout before first byte → 504 same shapes.
- All other statuses are upstream's (INV-15).
- A mid-stream upstream failure cannot change the already-sent status; close the stream and record `outcome="upstream_error"`.

### 9.7 Retry-with-original safety net
If the request was **mutated** (mode=active and any transform changed bytes) and upstream returns a status in `retry_original_on_status` (default 400, 422) **before any response bytes are streamed to the client**, then:
1. Close that response; resend the **original** bytes once.
2. Return the second response to the client.
3. Record `fallback_used=1`, the first error body (≤ 2 KB, redacted), and the transform reports. Dashboard surfaces these as "Transform regressions" with the offending request retained (if capture enabled).
Never retry on 401/403/429/5xx. Never retry streamed responses already begun. Never retry when the request was unmodified.

```python
    # Structure access for transforms/analysis (never copies payload; yields live handles)

    # Telemetry
    def new_usage_parser(self, ctx: RequestContext) -> UsageParser: ...
    def parse_usage_body(self, body: bytes) -> Usage: ...

    def error_body(self, status: int, message: str) -> tuple[bytes, str]: ...  # (body, content-type)
```
Adapters are the only place that knows provider JSON shapes. Transforms operate on `ToolResultRef` and a small set of adapter capability methods; they must not import provider modules.

### 11.1 Anthropic (`/v1/messages`)
Request shape (VERIFY against current docs):
- `model`, `max_tokens`, `stream`, `system` (string **or** list of text blocks), `tools[]`, `tool_choice`, `thinking`, `messages[]`.
- Cache prefix order: **tools → system → messages**. A `cache_control: {"type":"ephemeral","ttl":"5m"|"1h"}` marker on a block caches everything up to and including it.
- `messages[].content` is a string or list of blocks: `text`, `image`, `document`, `tool_use{id,name,input}`, `tool_result{tool_use_id,content,is_error}`, `thinking`, `redacted_thinking`.
- `tool_result.content` is a string or a list of `text`/`image` blocks. Resolve `tool_name` by mapping `tool_use.id → name` from preceding assistant messages.
Usage (streaming SSE; VERIFY):
- `message_start` → `message.usage` {`input_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`, optional `cache_creation{ephemeral_5m_input_tokens, ephemeral_1h_input_tokens}`, `output_tokens`}.
- `message_delta` → `usage.output_tokens` (cumulative; take the last value). Input fields may also be repeated — prefer the final non-null values.
- Non-streaming: `usage` object in the JSON body.
- **`input_tokens` excludes cache read/write tokens.** Normalization: `fresh_input = input_tokens`.
Known constraints (VERIFY, configure in `data/cache_limits.json`): max 4 breakpoints per request; minimum cacheable prefix length varies by model (e.g. 1024 / 2048 / 4096 tokens); `cache_control` not allowed on empty text blocks; thinking blocks can't carry it directly; changes to `tools`, `tool_choice`, `thinking` params, or system content invalidate downstream cache levels; ~20-block lookback window when searching for cache hits from a breakpoint; 1h TTL entries must precede 5m entries in prompt order; write premium ≈1.25× (5m) / ≈2× (1h), read ≈0.1× base input.

### 11.2 OpenAI Chat Completions (`/v1/chat/completions`)
- `messages[]` roles: `system|developer|user|assistant|tool`. `assistant.tool_calls[{id,type,function{name,arguments}}]`; tool outputs: `role:"tool"`, `tool_call_id`, `content` (string or parts).
- Usage: non-stream `usage{prompt_tokens, completion_tokens, prompt_tokens_details{cached_tokens}, completion_tokens_details{reasoning_tokens}}`. Streaming usage appears only if `stream_options.include_usage=true` (final chunk with empty `choices`). **Default: do not inject** `stream_options` (can confuse some clients); if absent, usage is `estimated` with `source="estimated"` and flagged. Provide opt-in `inject_stream_usage` config.
- Normalization: `fresh_input = prompt_tokens − cached_tokens` (prompt_tokens **includes** cached).
- Caching is automatic for sufficiently long identical prefixes (VERIFY thresholds/granularity); optional `prompt_cache_key` (and retention options, VERIFY) only on `api.openai.com`.

### 11.3 OpenAI Responses (`/v1/responses`)
- `input` is a string or a list of items (`message`, `function_call{call_id,name,arguments}`, `function_call_output{call_id,output}`, reasoning items…); `instructions`; `previous_response_id` (server-side state → there is nothing to compact; set `transformable=False` when present and rely on telemetry only).
- Usage in the `response.completed` event (`response.usage{input_tokens, input_tokens_details{cached_tokens}, output_tokens, output_tokens_details{reasoning_tokens}}`).
- Never alter reasoning items (INV-8).

### 11.4 Gemini (Phase 6)
- `contents[]` with `parts[]` (`text`, `functionCall`, `functionResponse{name,response}`, `inlineData`, thought parts); `systemInstruction`; `tools`; `cachedContent` reference.
- Usage: `usageMetadata{promptTokenCount, cachedContentTokenCount, candidatesTokenCount, thoughtsTokenCount, totalTokenCount}` (appears in chunks; take the last). `fresh_input = promptTokenCount − cachedContentTokenCount`.
- Streaming path `:streamGenerateContent` returns SSE when `alt=sse`, else a JSON array stream — support both in the parser or mark usage `none` for the array form in v1.
- Active transforms limited to string fields inside `functionResponse.response` (walk JSON, transform string leaves only for compactable tool names). Explicit `cachedContents` management is out of scope; implicit caching → diagnostics only.

### 11.5 Ollama (Phase 6)
- `/api/chat` NDJSON; final object has `done:true`, `prompt_eval_count`, `eval_count`, durations. Cost = $0; track tokens/latency only. Local KV-cache reuse depends on stable prefix → drift diagnostics still useful. `tool` role messages with `content` (+ `tool_name`).

## 12. Transform Engine

### 12.0 Framework

#### 12.0.1 Transform protocol (`transforms/base.py`)
```python
class Transform(Protocol):
    id: str
    def applies(self, ctx: RequestContext) -> bool: ...      # provider/mode/config gating
    def apply(self, ctx: RequestContext, payload: dict, adapter: ProviderAdapter) -> TransformReport: ...
```
- `apply` mutates `payload` in place and returns a report. It MUST be pure with respect to external state (INV-4) and idempotent (INV-5).
- Content-local text transforms are written as pure functions `str -> str` in the transform module (`def clean(text: str, cfg) -> str`) and wrapped by a thin driver that iterates `adapter.iter_tool_results(payload)`. **Pure functions are what the property tests target.**

#### 12.0.2 Token estimation (`analysis/tokens.py`)
- `estimate_tokens(text, family) -> int`: if `tiktoken` is installed *and* its encoding is available offline, use it (`o200k_base` for OpenAI family; `cl100k_base` as a rough proxy for others); otherwise `ceil(len(text) / 3.5)`.
- Calibration: when provider-reported input tokens are available, maintain an EMA ratio `actual / estimated` per model family (persisted in `meta`), applied to future estimates. All estimates remain labeled *estimated* (INV-13).
- Estimates are used for: no-regress guard, min-prefix checks, baseline simulation, dashboard "tokens saved". They are **never** used as billing truth.

#### 12.0.3 Marker format (all transforms that omit content)
Single-line, ASCII, token-cheap, recognizable, never itself transformed:
```
[ctxproxy: 412 lines (38.2 KB) omitted; ref=ab12cd34]
[ctxproxy: line repeated 57 more times]
[ctxproxy: output identical to earlier tool result toolu_01Abc... ]
[ctxproxy: tool result elided (21.4 KB); re-run the tool if needed]
```
`ref` = first 8 hex chars of sha256 of the original text (lets the dashboard find the stored original; omitted when payload capture is `off`).

#### 12.0.4 Eligibility matrix (tool-result classes from `[tools]` globs)
| Transform | `compactable` tools | unknown-name tools | `never_touch` tools (file reads/edits) |
|---|---|---|---|
| ansi_strip | ✅ | ✅ | ❌ |
| progress_collapse | ✅ | ✅ | ❌ |
| line_dedupe | ✅ | ❌ | ❌ |
| whitespace_trim | ✅ | ❌ | ❌ |
| smart_truncate | ✅ | ❌ | ❌ |
| duplicate_backref | ✅ | ✅ | ✅ if `include_never_touch=true` (default true; earlier copy stays intact) |
| cache_serve (opt-in; stateful, batch-anchored) | ✅ | ✅ | ✅ (byte-true T0 substitution with retrieval affordance — see §12.12) |
| stale_result_elision (opt-in) | ✅ | ❌ | ❌ |
`is_error=true` results: all transforms allowed, but smart_truncate must prioritize signal lines (§12.5).
Non-text blocks (images/documents) are never touched.

### 12.1 `ansi_strip`
Remove: CSI sequences `\x1b\[[0-?]*[ -/]*[@-~]`; OSC `\x1b\][^\x07\x1b]*(?:\x07|\x1b\\)`; other 2-char ESC sequences `\x1b[@-Z\\-_]`; remaining C0 control chars except `\n`, `\t`, `\r`. Keep Unicode text intact. Linear-time patterns only (no nested quantifiers).

### 12.2 `progress_collapse`
1. **Carriage-return overwrite:** for each line containing `\r`, keep the text after the last `\r` that is non-empty (terminal semantics).
2. **Progress lines:** a line is progress-like if it matches any of: bar glyph runs `[#=>█▉▊▋▌▍▎▏\-\. ]{8,}` plus `\d{1,3}%`; `\b\d+(\.\d+)?\s?(kB|MB|GB|KiB|MiB)/s\b`; leading verbs `Downloading|Fetching|Receiving objects|Resolving deltas|Compressing objects|Unpacking|Counting objects|Collecting|Installing` combined with a percentage or size. Collapse each *consecutive* run of ≥ 3 progress-like lines into the **last** line of the run plus `[ctxproxy: N progress updates collapsed]` on the line before it.
3. Never collapse lines containing `error|fail|fatal|warning` (case-insensitive).

### 12.3 `line_dedupe`
- Exact runs: `rstrip()`-equal consecutive lines, run length ≥ `min_repeat` → first line + `[ctxproxy: line repeated N more times]`.
- Near-duplicate runs: key = line with `\d+` → `#`, ISO-8601/`HH:MM:SS` timestamps → `<ts>`, hex ids (`[0-9a-f]{8,}`) → `<id>`; runs ≥ `2*min_repeat` keep first and last line, with `[ctxproxy: N similar lines omitted]` between. Never apply near-duplicate collapsing to lines matching the signal patterns in §12.5.

### 12.4 `whitespace_trim`
`rstrip()` each line; collapse blank-line runs longer than `max_blank_run`; strip trailing blank lines to a single `\n`; **never** modify leading indentation. Only for `compactable` tools (trailing whitespace can be meaningful in file content/diffs).

### 12.5 `smart_truncate` (error-aware)
Trigger: `len(text.encode()) > trigger_bytes`. Goal: result ≤ `target_bytes` (+ markers). Config invariant (validated): `target_bytes * 1.5 <= trigger_bytes` so output never re-triggers (INV-5).

Algorithm (all deterministic, line-oriented):
1. Split into lines. Pre-pass: replace any single line longer than `max_line_chars` with `line[:max_line_chars] + " [ctxproxy: line truncated, N chars]"`; replace base64-like runs (`[A-Za-z0-9+/=]{1000,}`) with `[ctxproxy: base64 blob, N chars]`.
2. Mark **must-keep** lines by priority, adding until the byte budget is exhausted:
   1. First `head_lines` lines (command echo, early errors).
   2. Last `tail_lines` lines (summary, exit codes, final errors).
   3. **Signal windows:** lines matching (case-insensitive) `error|fail(ed|ure)?|exception|traceback|panic|assert(ion)?|fatal|segfault|cannot|can't|undefined|not found|denied|timeout|exit (code|status)|npm ERR!|\bE\s{3}\S|^FAILED|^ERROR|error\[E\d+\]|^\s*File ".*", line \d+|\S+\.\w+:\d+(:\d+)?:` plus `context_lines` before/after each, capped at `max_signal_lines` lines. Python tracebacks and Rust/Go panics: keep the whole block (up to 100 lines) starting at `Traceback (most recent call last):` / `panic:` / `thread '...' panicked`.
   4. Summary lines: `\d+ (passed|failed|errors?|warnings?)`, `Tests?:`, `Test Suites:`, `Ran \d+ tests`, `BUILD (SUCCESS|FAILURE)`, `Finished|Compiling .* in`.
3. Emit kept lines in original order; each maximal omitted gap becomes one marker `[ctxproxy: N lines (X KB) omitted; ref=…]`.
4. If must-keep lines alone exceed `target_bytes * 1.5`, shrink in order: signal windows (keep first `max_signal_lines/2` and last half), then head, then tail — never drop summary lines.
5. If `is_error` is true, double `max_signal_lines`.
Edge cases: results that are valid JSON > 2×trigger → treat as plain text in v1 (document limitation); binary-looking content (NUL bytes) → leave untouched and add `notes["skipped"]="binary"`.

### 12.6 `duplicate_backref`
Within a single request, hash (sha256 of text after ansi/progress cleanup) every tool result ≥ `min_bytes`. For a later result whose hash equals an earlier result's hash **and the earlier result is still full text in this request**, replace the later text with the stub `[ctxproxy: output identical to earlier tool result <tool_use_id>]`. Properties: only later duplicates change, so the earlier prefix is untouched (INV-6 holds); decision is position-independent (no "recent" protection — adding one would break INV-6). Never reference a stub; never use a result from a different message role context (only tool results).

### 12.7 Pipeline order, budget, and guards (`pipeline.py`)
Order (fixed): `ansi_strip → progress_collapse → line_dedupe → whitespace_trim → smart_truncate → duplicate_backref → cache_serve → stale_result_elision → volatile_normalizer → anthropic_cache | openai_hints`. (`cache_serve` runs before `stale_result_elision` so in-request duplicates resolve to the stateless rule first; elision then removes what's already been accounted for.)
- Before the pipeline: compute **original segments** (§13.3) and original token estimate. After: compute **final segments**.
- Each transform runs in try/except; on exception: revert that transform's edits (work on a per-transform change journal: list of `(ref, old_text)`), mark `discarded_reason="error"`, continue with the next.
- No-regress guard (INV-10): if `est_tokens_before − est_tokens_after < min_saving_tokens`, revert the journal and mark `discarded_reason="no_regress"`.
- Time budget: after each transform check `time.perf_counter()`; if > `time_budget_ms` stop running further transforms (payload so far is valid), mark remaining as `discarded_reason="budget"`.
- Cache-marker transforms are not subject to the token-saving guard (they are not reductions); they have their own preconditions (§12.9).
- `mode=shadow`: run everything, then discard the payload mutations (forward original bytes) but persist reports and simulate optimized cost.

### 12.8 `stale_result_elision` (opt-in, batched, positional)
Purpose: drop very old, large `compactable` tool outputs. Deterministic boundary so the prefix only changes once per batch:
```python
turns = count_assistant_turns(payload)                         # adapter-provided
boundary = max(0, ((turns - keep_recent_turns) // batch_turns) * batch_turns)
# elide eligible tool results belonging to assistant turns with index < boundary
```
Replace with `[ctxproxy: tool result elided (21.4 KB); re-run the tool if needed]`; keep `tool_use_id` pairing (INV-7). Cost trade-off: each boundary advance causes one cache miss for the tail beyond the first elided block; recommend ≥ 8 for `batch_turns`. Dashboard must show a break-even estimate from the simulator before the user enables it. If the client compacts its own history so `turns` shrinks, previously elided results reappear — acceptable and deterministic.

### 12.9 `anthropic_cache` (cache_control injection)
Preconditions: provider=anthropic, endpoint=messages, mode=active, transform enabled, model not on the blocklist in `data/cache_limits.json`, not already at `max_breakpoints`.

Rules ("stair-step" strategy):
1. Count existing `cache_control` markers in `tools`, `system`, and `messages` blocks (`n_existing`). If `respect_existing`: never move/remove them; add at most `max_breakpoints − n_existing` (hard cap 4 total).
2. **BP-A static prefix:** last block of `system` (convert string `system` to `[{"type":"text","text":<str>}]` — lossless); if no `system`, the last entry of `tools`. Only if estimated tokens of tools+system ≥ model minimum cacheable length (from `cache_limits.json`; VERIFY values).
3. **BP-C previous-turn tail:** last cacheable block of `messages[-3]` (the last message before the most recent assistant message). This equals the previous request's tail, guaranteeing a read hit independent of the ~20-block lookback window. Only if `len(messages) >= 3`.
4. **BP-D current tail:** last cacheable block of `messages[-1]`. Only if `len(messages) >= 3` or a prior request in this session was within TTL (avoids paying the write premium on one-shot calls).
5. Cacheable block = `text` (non-empty), `tool_use`, `tool_result`, `image`, `document`; skip `thinking`/`redacted_thinking`/empty text. If the chosen block already has `cache_control`, skip.
6. `ttl`: omit field for 5m; include `"ttl":"1h"` only when configured. If mixing TTLs, 1h markers must come earlier in the prompt than 5m markers.
7. Report: which breakpoints added, `n_existing`, estimated cacheable tokens. If the client already uses breakpoints well (Claude Code), the transform is typically a no-op — that is a valid and expected outcome; the dashboard's "Cache Health" shows *client marker quality*.
8. Changing `tools`, `tool_choice`, `thinking`, or system content between requests invalidates cache regardless of markers — handled by the drift detector (§13.4), not by this transform.

### 12.10 `openai_hints`
Only when upstream host is exactly `api.openai.com`, endpoint ∈ {chat, responses}: if the payload lacks `prompt_cache_key`, set it to an opaque value `ctxp-` + first 24 hex of HMAC(install_secret, session_id). Never overwrite a client-provided key. VERIFY parameter name/semantics in current docs before shipping; the config flag stays default-off until verified with real captures showing improved `cached_tokens`.

### 12.11 `volatile_normalizer` (experimental, default off)
Detects volatile tokens inside `system` text (and the first user message env block): `Current date|Today's date|Current time|Date:` followed by a date/time, ISO timestamps, UUIDv4, epoch seconds in `<env>`-style blocks. Rewrites time precision to day granularity (`2026-10-24T13:05:11Z → 2026-10-24`). Violates INV-9 deliberately (mutates system text) → requires explicit opt-in and a dashboard warning. The drift detector recommends it only when it observed system-prompt drift caused by such tokens in ≥ 3 consecutive requests.

### 12.12 `cache_serve` (byte-true cross-request substitution)

Purpose: the largest recurring waste after cache misses itself — **the same unchanged file content billing as fresh input on every turn it is re-read**, forever (each re-read also drags a full cache-write premium). `duplicate_backref` (§12.6) only dedupes identical tool results *inside one request*; `cache_serve` extends the same idea across turns using per-session state.

**Safety class: T0 (byte-true).** A stub is only ever emitted when the new tool result's content hash equals the stored hash of content the session has already held. The stub states *true facts only*. This is not an approximation — it is the same bytes, not paid for.

Stub format (reuses the marker grammar, §12.0.3):
```
[ctxproxy: content identical to that retrieved at turn T (8.2 KB, sha256 ab12cd34...); unchanged.
 reread ref=ab12cd34 | ctxproxy_expand(ab12cd34) retrieves it]
```

Algorithm (per request, after other transforms):
1. For each eligible tool result ≥ `min_bytes` (tool name must be in `compactable` ∪ (`never_touch` when `include_never_touch`)): compute `h = sha256(sigma-stripped text)` (sigma = ANSI/progress cleanup first, so cosmetic noise doesn't defeat the hash).
2. Look up `h` in the **session content map** (bounded LRU: `max_state_sessions` sessions × `max_entries_per_session` entries; entries store: hash, full sha256, size, turn_first_seen, blob availability flag).
3. If `h` is present **and** the request contains an earlier un-stubbed block with the same hash → behave exactly like `duplicate_backref` (stateless rule wins; stays byte-true and position-independent per §12.6).
4. Else if `h` is present **only in session state** (the earlier full copy is no longer in this request — most commonly because the client compacted its own history): substitute the *later* occurrence with the stub. This is the stateful case.
5. Else (first sighting): record `h`→entry in the session map (and store the original in the blob store so `expand` can serve it later); keep full text.

Cache-safety scheme (INV-17 — same construction as §12.8):
- Mappings only "activate" at **batch boundaries**: `boundary = max(0, ((turns - keep_recent_turns) // batch_turns) * batch_turns)`; substitutions are only emitted for turns with index ≥ the current boundary. Extending the conversation therefore never rewrites the serialized prefix except when the boundary advances (one deterministic cache miss per `batch_turns` turns, priced by the break-even estimator before a turn is allowed to elapse it).
- Idempotence (INV-5): second application on the same request produces no change (normalized-hash → stub is stable; a stub never re-hashes into a substitution).
- Determinism (INV-4): decision inputs = request content + per-session map + config only.

Preconditions & guardrails:
- Requires `capture_payloads != off` (the blob store is what makes `expand` possible); if capture is off the transform refuses to enable and `ctxproxy doctor` says so.
- Stub count per request ≤ `max_stubs_per_request`; per-session state eviction is LRU and logged.
- The stub always carries the re-fetch affordance ("re-run the tool" and/or `expand` ref) — the agent is never left without a path to the original bytes.
- Guard (§12.14) applies in full: any fallback or client-side complaint that correlates with `cache_serve` quarantines it.

Non-goals/note: no embedding/semantic similarity — hash identity only. Similar-but-different content stays untouched (that problem is deliberately unsolved; it needs judgment we refuse to fake).

### 12.13 `ctxproxy_expand(ref)` — on-demand original retrieval (MCP stdio server)

Promoted from "v2 idea" to Phase 3 scope: on-demand retrieval is what makes truncation-side transforms trustworthy ("lazy loading" instead of "data loss").

- `ctxproxy mcp run` starts a minimal MCP **stdio** server (stdlib JSON-RPC; no SDK dependency). Register it as an MCP server in the client (`claude mcp add ctxproxy -- ctxproxy mcp run` or per-client config; `ctxproxy doctor` prints ready-made snippets and VERIFYs per client).
- Single tool: `ctxproxy_expand(ref: str, max_tokens: int | None = None)`. `ref` = full sha256 or its 8-hex prefix (ambiguous prefix → error listing matches). Returns the **zlib-decompressed original** from the blob store, truncated head+tail with the standard marker grammar if `max_tokens` exceeded.
- Trust model: reads only `ctxproxy`'s own data dir (POSIX `0600`); loopback-only companion HTTP endpoint (`/_ctxproxy/api/expand/<ref>`) for HTTP clients; **no network egress**; honors `purge` and retention.
- If the blob is missing (retention, purge, or capture=off): returns an honest error — the stub's re-run-the-tool affordance is the fallback path, never a broken reference.
- Privacy: retrieval is logged (ref, ts) but never the content; dashboard shows "expand usage" only as a counter (it's a strong hint that a transform over-truncated — feeds the guard).

### 12.14 Auto-quarantine guard (self-tuning, always on when `[guard].enabled`)

Sliding window per transform × session, fed by existing counters — no new plumbing, just policy:

| Signal (from telemetry) | Rule | Action |
|---|---|---|
| `fallback_used` | > `fallback_limit` within last `fallback_window` mutated requests | transform → shadow for the session; dashboard alarm w/ evidence links |
| `drift_events` stream=`final`, any cause | ≥ `our_fault_drift_limit` occurrence | involved transforms → shadow immediately; alarm pinned on Overview |
| est. savings | < `min_savings_to_stay` USD over window while active | transform → shadow ("overhead without benefit") |
| expand error rate for a transform's refs | > 20% of its expand calls erroring | that transform → shadow (broken retrieval = broken stub) |

Properties: quarantine is **session-scoped and reversible** (`ctxproxy guard enable <transform>` / dashboard button; also auto-re-enables after N clean shadow sessions if `guard.auto_reenable = N > 0`). Quarantine events append to a new `guard_events` table (same schema pattern as `drift_events`). Rationale (D17): the product tunes itself per codebase — the trust story ("it never fights you") is a feature competitors auditors can't copy.

## 13. Analysis Layer

### 13.1 Session & project identification (`analysis/session.py`)
Precedence for `session_id`:
1. `x-ctxproxy-session` header.
2. Client-provided session headers (VERIFY, e.g. Claude Code may send one).
3. Derived: `sha256(provider | key_fingerprint | blake2b(system_text[:4096] + tools_names_joined) | blake2b(first_user_text[:2048]))[:16]`.
`key_fingerprint` = `HMAC-SHA256(install_secret, api_key_or_bearer)[:12]` — the raw key is never stored (INV-11). Requests lacking system/tools (aux calls like title generation) form separate sessions tagged `kind="aux"` when `tools` absent and total tokens < 2000; dashboard groups by project and hides aux by default.
`project`: `x-ctxproxy-project` header > `/p/<project>/` prefix > regex on system/first user text (`Working directory:\s*(\S+)`, `<cwd>(.*?)</cwd>`, `Primary working directory:` — VERIFY per client) → **basename only** > `"default"`.

### 13.2 Client identification
From `User-Agent`: `claude-cli`/`claude-code` → `claude-code`; `aider` → `aider`; `OpenAI/Python` → `openai-sdk`; `Anthropic/Python` → `anthropic-sdk`; `python-httpx`, `node`, `curl` → as-is. Unknown → `unknown`.

### 13.3 Segments & hashing (`analysis/segments.py`)
Canonical order per provider = prompt order (Anthropic: tools, system blocks, message blocks; OpenAI chat: messages in order with tool schemas first; Responses: instructions, tools, input items; Gemini: systemInstruction, tools, contents parts).
```python
@dataclass(frozen=True, slots=True)
class Segment:
    kind: Literal["tool_def","system","message"]
    msg_index: int | None
    block_index: int | None
    hash: bytes            # blake2b-8 of orjson.dumps(block, option=OPT_SORT_KEYS) with "cache_control" removed
    est_tokens: int
    has_marker: bool
```
Cumulative token position per segment is derived on demand. Also hash the "params fingerprint": `model`, `tool_choice`, `thinking`, `temperature`-class params relevant to caching (provider-specific list), so param drift is detectable.

### 13.4 Prefix-drift detector (`analysis/drift.py`) — the diagnostic centerpiece
State: per session keep last 3 **original** and last 3 **final** segment lists + timestamps + config_hash (in-memory LRU of 256 sessions).
Given previous list `P` and current list `C`, expected: `P` is a prefix of `C` (conversation only appends). Compute first index `i` where they differ (or `None`). If `i is not None` and `i < len(P)` → **drift event** with:
| cause | detection |
|---|---|
| `tools_changed` | divergence inside tool_def segments (report added/removed/reordered tool names) |
| `system_changed` | divergence in system segments; include a ≤ 20-line unified diff and flag volatile tokens (dates/UUIDs/timestamps) |
| `params_changed` | params fingerprint differs (model/tool_choice/thinking) |
| `history_mutated` | divergence inside message segments (client compaction, edited history, changed earlier tool result) |
| `ttl_expired` | no content divergence but `Δt > ttl` (Anthropic 5m/1h config; OpenAI ~5–10 min VERIFY) |
| `config_changed` | `config_hash` differs from previous request (our own change) |
| `model_switched` | model differs (separate cache namespace) |
`est_tokens_lost` = sum of `est_tokens` of segments in `C` from `i` to the end of `P`'s extent (what could have been a cache read). Run the detector on both the **original** stream (client's fault → advisory) and the **final** stream (our fault → alarm; must trigger a visible warning and a test failure in CI fixtures).

### 13.5 Baseline simulator (`analysis/baseline.py`)
Purpose: estimate what the *untouched* request would have cost, for honest savings display. Pure function:
```python
simulate_cache(provider, model, prev: SegList|None, prev_ts, cur: SegList, cur_ts, client_marker_positions, limits) -> CacheSim
CacheSim = (fresh_tokens, read_tokens, write_5m_tokens, write_1h_tokens)
```
Rules (parameters in `cache_limits.json`; VERIFY and keep dated):
- **Anthropic:** if the *original* payload has no `cache_control` markers → no reads/writes (everything fresh). Else: `L` = token length of common prefix between `prev` and `cur`; `read = min(L, tokens up to prev's last marker position)` if `Δt ≤ ttl` else 0; `write` = tokens from end of `read` up to `cur`'s last marker position; `fresh` = remainder.
- **OpenAI / Gemini implicit:** `read = floor(L / 128) * 128` if `L ≥ min_prefix` (1024 default; VERIFY per model) and `Δt ≤ implicit_ttl` (default 600s) else 0; no write fees.
- **Ollama:** cost 0; track tokens only.
Outputs:
- `cost_baseline_sim` = simulate(original segments) priced with the model's rates + actual output tokens.
- `cost_optimized_sim` = simulate(final segments incl. injected markers).
- In **active** mode, `cost_actual` comes from provider usage. Record `sim_read_optimized` vs actual `cache_read` to display a **calibration error** (percent difference) — if it exceeds 25% over the last 50 requests, show "savings estimates unreliable for this client" instead of numbers.
- Savings shown: active → `baseline_sim − actual` (labeled *estimated*); shadow → `baseline_sim − optimized_sim` (labeled *potential*).

### 13.6 Waste detectors (`analysis/waste.py`) — the attribution centerpiece

All detectors are **deterministic, advisory-only (INV-16), evidence-linked, and deduplicated**: one open Finding per `(session_id, detector, key_hash)` with `occurrences++` while `now − last_seen_ts < dedupe_window_min`. Findings record `evidence` (turn numbers, block hashes, `ref`s — never raw text) and a priced estimate whose method is stated per detector (INV-18).

| ID | Detector | Deterministic definition | `est_tokens_wasted` method | Default |
|---|---|---|---|---|
| **W1** | `redundant_reread` | Tool-result hash `h` (≥ `min_bytes`, sigma-stripped) already seen earlier **in this session** (any prior turn, in-request or not) | token estimate × duplicate occurrences − what transforms already removed | on |
| **W2** | `identical_output` | Same tool result hash ≥ 3× in one session (polling/retry churn pattern distinct from W1's file rereads) | median occurrence tokens × (n − 1) | on |
| **W3** | `unbatched_fanout` | ≥ `min_calls` sequential read-like tool calls (name ∈ read globs) in one assistant turn, mutually exclusive file targets | Σ per-call round-trip overhead ≈ fresh-input tokens of the *later* calls retried as separate requests (bounded, conservative) | on |
| **W4** | `runaway_session` | Inter-turn gap > `idle_gap_s` inside an active session (`min_turns` reached) — the agent "kept working" unattended | fresh_input (+ write premium) of the first request after the gap = the re-billed prefix | on |
| **W5** | `recurring_drift` | Same `drift_events` cause on the *original* stream ≥ `min_occurrences` times with the same segment signature — a recurring **client-side** cache bust | Σ `est_tokens_lost` of contributing events | on |
| **W6** | `params_drift` | `params_changed` / `model_switched` frequency per session (from the params fingerprint, §13.3) | Σ lost cache reads across the session | on |
| **W7** | `churn_detector` | Assistant edit (tool_use input) whose new value reverts a previously applied value (hash match against prior input values), or changes only whitespace | Σ billable delta of the touching turns | **off (Phase 6)** |
| **W8** | `schema_bloat` | tool-schema segments never referenced by any `tool_use` in the session | their est_tokens × (session request count − 1) | on (Phase 6) |

Rollups: per-session, per-project, and per-cause totals (tokens + `est_cost_usd` at the request's model pricing) power the dashboard's **Waste Opportunities** page (§16.2) and `ctxproxy waste`. ARanking is by `est_cost_usd × occurrences`, newest first within equal rank.

Detector-to-result plumbing: W1/W2 consume the per-request *original* segment list (pre-transform); the same finding that justifies an enabled `cache_serve` appears as W1 with `actionable=cache_serve`. Findings whose actionable target is already on are marked `fixed` automatically once the corresponding metric flattens (4 consecutive windows below threshold).

### 13.7 Recommendations engine (`analysis/recommend.py`)

Pure function of recorded telemetry → ranked suggestions. **Never auto-applies**; one-click "apply" writes config via the admin API with a confirm dialog and a config_hash annotation (§7.1). All projections carry `est.`/`sim.` labels and derive from the simulator rules (§13.5) — no invented economics.

| Suggestion | Trigger (measured evidence) | Projected saving source |
|---|---|---|
| Enable `volatile_normalizer` / fix client timestamp | system_p drift ≥ 3 consecutive requests containing volatile tokens (§12.11) | sim: restored cache reads |
| Enable `cache_serve` | W1 above sim break-even for ≥ 2 sessions | sim: W1 est tokens × cache-write premium |
| Prune MCP servers | W8: tool schemas unused in 10+ session-requests | sim: schema tokens × req count |
| Batchreads / config hint | W3 recurring in ≥ 3 turns | advisory text; no sim claim |
| Investigate client behavior | W4 ≥ 2×, W5 same-cause ≥ 3× | advisory text |
| Disable under-performing transform | guard would-quarantine (low savings, no regressions to justify keep-alive) | saves compute overhead (no client-facing $ claim) |
| Capture policy upgrade | `cost_baseline_sim` calibration error > 25% | honesty nudge, not savings |

Suppression: one open suggestion per trigger; dismissed/ignored suggestions are remembered per project (status `skipped`) and not re-surfaced for 30 days.

### 14.2 Pricing (`data/pricing.json`, user-overridable)

```json
{
```

### 16.2 Pages

## 18. Performance Budgets & Concurrency

| Metric | Target |
|---|---|
| Added latency (decode+analyze+transform+encode), payload ≤ 500 KB | p50 ≤ 5 ms, p95 ≤ 25 ms |
| Payload ≤ 5 MB | p95 ≤ 150 ms (offloaded to thread) |
| Passthrough overhead on streaming chunk | < 0.2 ms per chunk (no per-chunk allocations beyond parser feed) |
| Concurrent streams | 50 without event-loop stalls > 50 ms |
| Memory (RSS) steady state | < 150 MB with 256 cached sessions |
| Cold start | < 1.5 s to listening |
| Telemetry queue | bounded 10k; drop-with-counter on overflow, never block |
Implementation rules:
- Parse JSON once (`orjson.loads`), mutate in place, serialize once.
- Avoid deep copies; the change journal stores only `(ref, old_text)` of touched blocks.
- Precompile regexes at import; process line-by-line; no unbounded backtracking.
- Large payloads (> `offload_threshold_bytes`) run via `asyncio.to_thread`; if event-loop lag (measured with a 100 ms heartbeat task) exceeds 100 ms p95 in `bench`, move the pipeline to a `ProcessPoolExecutor(max_workers=2)` (documented fallback; mind PyInstaller `freeze_support`).
- `scripts/bench.py` runs a fixed corpus (small/medium/large captured conversations), reports p50/p95/p99 overhead, and fails CI if p95 regresses > 20% vs the committed baseline.
- Publish the measured numbers; do not claim "<2 ms".

## 20. Testing Strategy

### 20.1 Layers
1. **Unit** — pure functions: each text transform, redaction, SSE/NDJSON parsers, pricing match, cost math, segmenter, drift classifier, simulator.
2. **Golden** — `tests/golden/<case>/{input.json,config.toml,expected.json,notes.md}`; runner applies the pipeline and compares serialized output + reports. Regenerate with `UPDATE_GOLDEN=1 pytest tests/golden` (diff reviewed by a human). Seed corpus (minimum): pytest failure output (long), `npm install` progress, `cargo build` warnings flood, Python traceback, repeated file reads, giant minified-JS line, base64 blob, JSON tool result, Claude-Code-style conversation with existing `cache_control`, OpenAI tool-call conversation, Responses `function_call_output`, conversation with `thinking` blocks, parallel tool calls.
3. **Property tests (hypothesis)** — for every transform and the whole pipeline:
   - **P1 Idempotence** `f(f(x)) == f(x)` (INV-5).
   - **P2 Determinism** same input → same output across runs and `PYTHONHASHSEED` values (run in subprocesses) (INV-4).
   - **P3 Prefix stability** generate conversation `C` and extension `C+Δ`; serialized transformed segments of `C` are a prefix of those of `C+Δ` for content-local transforms and for `duplicate_backref` (INV-6). For elision: prefix identical except at batch boundaries.
   - **P4 Pairing** every `tool_use`/`tool_call` ID still has exactly one matching result, order preserved (INV-7).
   - **P5 Unknown-field preservation** random extra keys at every level survive; untouched blocks are byte-identical after serialization (INV-7).
   - **P6 No-regress** transformed token estimate ≤ original unless only cache markers were added (INV-10).
   - **P7 Reasoning untouched** thinking/reasoning blocks are identical (INV-8).
   - **P8 Linear time** adversarial strings (long runs of `\x1b[`, `=`, spaces, digits) complete within a time bound proportional to length (SEC-8).
4. **Integration** — real proxy app (uvicorn on ephemeral port) + fake upstream server (Starlette) that replays recorded SSE streams with controllable chunk sizes/delays. Cases: streaming passthrough byte-equality; usage extraction for each provider (stream and non-stream); client disconnect mid-stream (upstream closed, outcome recorded); upstream 429 passthrough with headers; upstream 400 on mutated request → retry-with-original success + `fallback_used`; connect failure → 502 provider-shaped body; large body > `max_body_bytes` streamed through; gzip request body; unknown route passthrough; `count_tokens` passthrough; query string preservation (`?beta=true`, Gemini `key`/`alt`); admin endpoints rejected with bad Host/token; telemetry queue overflow doesn't block.
5. **Contract (live, opt-in, skipped by default)** — `pytest -m live` with real API keys: minimal requests per provider verifying usage parsing, cache markers accepted (no 400), and `cached_tokens`/`cache_read_input_tokens` increase on the second identical-prefix call. Results appended to `docs/provider-notes.md`.
6. **Client smoke checklist (manual, per release)** — Claude Code session of ≥ 20 turns through proxy in shadow then active: no errors, savings visible, no drift "our-fault" events. Same for an SDK script and Aider.
7. **Benchmarks** — §18.

Gates: `ruff check`, `ruff format --check`, `mypy --strict`, `pytest -q --cov` (≥ 90% on `transforms/`, `analysis/`, `telemetry/usage.py`; ≥ 80% overall), `pip-audit`, bench regression check, wheel build + install smoke test (`ctxproxy --version`, start/health/stop).

## 23. Risk Register

| Risk | Impact | Mitigation |
|---|---|---|
| Providers/clients ship native context management or better caching, shrinking savings | Lower value | Lead with measurement + cache diagnostics (durable); make transforms individually toggleable; track results per client. |
| Transform degrades agent quality (e.g., truncation hides the needed line) | Trust loss | Signal-aware truncation, `never_touch` for file content, shadow-first onboarding, per-transform kill switch, retry-with-original, quality dogfooding log. |
| Cache busts caused by our own changes | Negative savings | INV-4/5/6 property tests, "our-fault" drift alarm, config-change annotation, no positional transforms by default. |
| Provider API changes (fields, thresholds, headers) | Breakage | `cache_limits.json`/`pricing.json` data-driven, `docs/provider-notes.md` with verification dates, live contract tests, fail-open. |
| Cursor/other clients can't be proxied locally | Market size | Honest compatibility table; focus on CLI/SDK/extension clients. |
| Privacy/security concerns (code in DB) | Adoption | Local-only, capture off/limited by default, redaction, purge, clear docs. |
| Python distribution friction (AV flags, size) | Install failures | `uv tool install` as primary path; sign binaries; provide checksums. |
| Savings claims perceived as inflated | Reputation | INV-13 labeling; publish methodology; show calibration error. |
| Event-loop stalls under big payloads | Latency | Chunked line processing, offload threshold, process-pool fallback, benchmarks in CI. |
| Waste detectors produce noisy/embarrassing findings | Trust | Evidence-required definitions, occurrence dedupe, `est.` labeling with stated method, ack/skip status, detector-level toggles, tuned-defaults after dogfood. |
| `cache_serve` confuses agents with stub-heavy context | Agent quality | T0 byte-truth only, stub affordances (re-run / expand), `max_stubs_per_request`, batch boundaries, guard quarantines on expand-error rate. |
| Expand server unavailable (capture off) | Broken promise | Hard enable-refusal + doctor check + stub degrade path ("re-run the tool"); never ship a dangling ref. |
| Vendors add native context management, shrinking transform value | Lower value | Waste attribution + recommendation layer is client-agnostic and model-agnostic (durable); per-transform toggles keep value modular. |

## 27. Glossary
- **Prefix cache:** provider-side reuse of the processed beginning of a prompt when it matches exactly.
- **Breakpoint:** Anthropic `cache_control` marker; everything up to and including that block is cacheable.
- **Segment:** hashed unit of the prompt in canonical order (§13.3).
- **Content-local transform:** output for a block depends only on that block's text/config (cache-safe).
- **Positional transform:** output depends on position in the conversation (cache-risky; batched).
- **Drift:** divergence between consecutive requests' prefixes that breaks cache reuse.
- **Shadow mode:** analyze and report, forward original unchanged.
- **Simulated baseline:** modeled cost of the untouched request, using the cache rules in §13.5.
- **Fail-open:** on proxy error, forward the original request.
- **Waste:** recorded spend attributable to a deterministic, evidenced, avoidable cause (§13.6) — always labeled `est.` (INV-18).
- **Waste detector / Finding:** deterministic rule producing an advisory record (INV-16); a Finding may mature into a Transform or a Recommendation, nothing more.
- **T0 substitution:** replacement of content by a hash-provably-identical stub + retrieval affordance (§12.12) — zero semantic risk.
- **Auto-quarantine:** per-transform, session-scoped demotion from active to shadow when guard counters trip (§12.14); reversible.
- **Retrieval affordance:** the pointer in a marker (`ref` / re-run hint) that guarantees the agent can always recover the original bytes (§12.13).
- **Recommendation:** ranked, evidence-backed config/behavior suggestion with simulated-but-labeled savings projection (§13.7); applied only via explicit user action.

## Appendix C — Minimal request flow pseudocode
```python
async def handle(request: Request) -> Response:
    route = router.classify(request)                       # §8
    if route.endpoint is Endpoint.PASSTHROUGH or route.mode is Mode.PASSTHROUGH:
        return await forward_raw(request, route)
    raw = await request.body()
    ctx = None; out = raw; reports = []; mutated = False
    try:
        payload = orjson.loads(raw)
        ctx = build_context(request, route, payload)       # session/project/client
        orig_segments = adapter.segments(payload)          # BEFORE transforms
        reports = await run_pipeline(ctx, payload)         # journals, budget, guards
        final_segments = adapter.segments(payload)
        if ctx.mode is Mode.ACTIVE and any(r.changed for r in reports):
            out = orjson.dumps(payload); mutated = True    # INV-2: only if changed
    except Exception:
        out, mutated = raw, False                          # INV-1 fail-open
    resp = await forward(route, out, original=raw, mutated=mutated)  # §9.3, §9.7
    schedule_telemetry(ctx, orig_segments, final_segments, reports)  # never blocks
    return resp
```
